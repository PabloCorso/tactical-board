# Domain Docs

This repo has one domain context.

Before changing code:

- Read relevant terms and relationships in `CONTEXT.md`.
- Read ADRs related to the area being changed.
- Use the glossary's vocabulary in issues, proposals, code, and tests.
- Surface contradictions with an ADR explicitly.

Add vocabulary or decisions only when they are resolved and durable; do not use
domain docs as a backlog or speculative design space.
